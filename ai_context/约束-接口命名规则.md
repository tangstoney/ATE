### 1. 接口风格总原则（第 9 节）需补充配置结构体初始化规范

ESP-IDF 官方 API 约定明确要求：**所有配置结构体的所有字段必须被初始化**，推荐使用 C99 指定初始化器（designated initializer）或框架提供的默认宏（如 `HTTPD_DEFAULT_CONFIG()`）。未初始化字段会导致未定义行为，这是 ESP-IDF 中一类常见的隐性 Bug 来源。[[API 约定](https://docs.espressif.com/projects/esp-idf/zh_CN/latest/esp32p4/api-reference/api-conventions.html)]

建议在第 9 节补充一条：

> - Driver 层配置结构体必须完整初始化，优先使用指定初始化器（`= { .field = val }`）；若组件提供默认宏，优先使用默认宏再覆盖特定字段。

---

### 2. Opaque Handle 设计已有明确参考实现

第 9 节提到"Driver 层优先使用 opaque handle"，这与 ESP-IDF 的官方设计风格完全一致。官方博客中有具体示例说明 handle 本质是指向内部结构体的不透明指针，对外只暴露函数接口：[[OOP in C](https://developer.espressif.com/blog/2025/10/oop_with_c/#handles-in-esp-idf)]

```c
// ESP-IDF 风格示例：handle 是不透明指针
typedef struct spi_device_t * spi_device_handle_t;

spi_device_handle_t handle;
spi_bus_add_device(VSPI_HOST, &devcfg, &handle);
spi_device_transmit(handle, &trans);
```

建议在总纲或专题文档中明确：Driver 层头文件只暴露 `xxx_handle_t` 类型和函数声明，内部结构体定义放在 `.c` 文件中，避免上层通过 `->` 直接访问内部字段。
